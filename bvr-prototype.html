Value Realized

The Business Value Realization dashboard provides insight into the incident management metrics for a subdomain and the value a customer is getting from the product over time.

How to use this Dashboard

  • Select the customer, then the start month and end month to set the timeframe.
  • On the graphs, use Segment bars by to split the bars by urgency or priority.
  • Time period switches the graphs between monthly and quarterly. For quarterly, pick start and end months on quarter boundaries, not the middle of a quarter, because the value metrics compare the first and last period.
  • Customer, month and time period apply to the whole view. Urgency and priority apply to the graphs and the MTTA/MTTR metrics, not to the funnel.
  • Quarters are regular calendar quarters, not the fiscal calendar.
  • Hover or focus any Value Realized tile to see its formula with the current numbers.

Data Sources

  • ACCEPTED_EVENTS_AIOPS_VW – events, alerts and suppression flags per month
  • INCIDENTS – incident counts and time to acknowledge / resolve, by priority and urgency
  • ACCOUNT – customer subdomain and renewal date

Prototype: every number here is synthetic, generated in the browser from a fixed seed, so it is identical on every load.

Notes

  • The funnel only counts events received through the Events API. Incident counts on the graphs can differ from the funnel because they also cover incidents created manually, through ticketing integrations or the REST API.
  • Numbers can differ slightly from in-product analytics because of how MTTA and MTTR are benchmarked, time zone differences and data refresh timing. With all filters removed over the same period, the two match.
  • MTTA and MTTR are incident-weighted: total minutes divided by incident count for whatever period and filters are selected.

Measures

Noise Reduction Funnel (Cumulative Volume)

  • Events: number of accepted events
  • Alerts: number of alerts after deduplication
  • Post Suppressed Alerts: number of alerts where is_suppressed = '0'
  • Incidents: number of unique incidents
  • Reduction % between tiers: 1 - (lower tier / upper tier)

Graphs

  • Number of incidents (segmented by urgency / priority)
  • MTTA / MTTR: Mean Time to Acknowledgement / Mean Time to Resolution, in minutes

Value Realized Metrics

  • Incidents Avoided: Alerts - Incidents
  • Noise Reduction: 1 - (Incidents / Alerts)
  • MTTA Efficiency: % change between the MTTA of the end period vs the start period. 1 - (End Period MTTA / Start Period MTTA)
  • MTTA Difference: absolute difference between end and start period MTTA. |End Period MTTA - Start Period MTTA|
  • MTTR Efficiency: % change between the MTTR of the end period vs the start period. 1 - (End Period MTTR / Start Period MTTR)
  • MTTR Difference: absolute difference between end and start period MTTR. |End Period MTTR - Start Period MTTR|
  • Hours Re-Allocated (Hours saved): Noise Reduction Hours + MTTA Difference Hours + MTTR Difference Hours
    1. Noise Reduction Hours = ((0.5 * (Alerts - Post Suppressed Alerts)) + (10 * (Post Suppressed Alerts - Incidents))) / 60
    2. MTTA Difference Hours = Acknowledged Incidents * MTTA Difference * 0.25 / 60. Set to 0 if MTTA got worse, since that would give negative hours.
    3. MTTR Difference Hours = Resolved Incidents * MTTR Difference * 0.1 / 60. Set to 0 if MTTR got worse, since that would give negative hours.
  • FTE Saved: Hours Re-Allocated / 2,000 working hours

Start period and end period are the first and last month (or calendar quarter) in the selected range.

Automated Actions

  • Deduped Alerts: avoids duplicate alerts by merging events into single alerts.
  • Escalations on Incidents: to guarantee critical issues are addressed promptly, incidents automatically escalate to the next responders.
  • Notifications: multiple notification channels contribute to faster acknowledgement times.
