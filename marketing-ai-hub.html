A custom MCP server, in code

simple examples, Python SDK

A custom server is worth building when a vendor's server is too broad or signs in the wrong way. It exposes a few narrow tools, and Claude can only do what those tools allow. The stand-in tool names on this page, such as query_leads and clone_program, are the kind of tools a custom server offers in place of one generic query tool.

1. The server: one read-only tool and one draft-only write tool
# server.py: a custom MCP server with two narrow tools.
# Setup: pip install mcp   (Python SDK v2)
from mcp.server.mcpserver import MCPServer
from mcp.server.mcpserver.exceptions import ToolError
from mcp.types import ToolAnnotations

mcp = MCPServer("marketing-data")

# Sample rows so this file runs as-is. In production, call your CRM
# with the signed-in user's token so their own permissions apply.
LEADS = [
    {"name": "M. Okafor", "campaign": "finops-summit", "hours_idle": 96},
    {"name": "G. Pemberton", "campaign": "close-faster", "hours_idle": 50},
    {"name": "A. Lund", "campaign": "close-faster", "hours_idle": 12},
]

@mcp.tool(annotations=ToolAnnotations(read_only_hint=True))
def query_leads(no_activity_hours: int = 48,
                campaign: str | None = None) -> list[dict]:
    """New leads with no logged activity for N hours. Read-only."""
    rows = [l for l in LEADS if l["hours_idle"] >= no_activity_hours]
    return [l for l in rows if campaign in (None, l["campaign"])]

@mcp.tool(annotations=ToolAnnotations(destructive_hint=False))
def clone_program(template: str, name: str) -> dict:
    """Clone a Marketo program template as a DRAFT. Never sends."""
    if not name.startswith("FY"):
        raise ToolError("Name must follow the convention, "
                        "e.g. FY26Q4-WBN-Topic-20261112")
    # production: call the Marketo program-clone API here
    return {"program": name, "template": template,
            "status": "draft", "activated": False}

if __name__ == "__main__":
    # serves http://127.0.0.1:8000/mcp
    mcp.run(transport="streamable-http", port=8000)

Tested with version 2.2.0 of the MCP Python SDK: the tool definition and the results in boxes 3 and 4 are real output from this code, trimmed. In SDK version 1 the class is named FastMCP. The example has no sign-in and uses sample rows. A production server adds OAuth, so every call runs as the signed-in user, and swaps the sample rows for real API calls. It can also bridge a sign-in gap: Adobe's Marketo server expects API keys in request headers, while Claude's custom connector screen takes a URL and OAuth details, so a small server in front can hold the keys and allow drafts only.

Safeguards in the design

  • Per-user sign-in. No shared accounts on the five rollout systems, so each applies that person's own permissions. Marketo's server takes an API user instead, so its role is limited to drafts.
  • Read-only at the server where possible. Salesforce through its read-only endpoint, Snowflake through a role limited to marketing views.
  • Three kinds of write only. A Slack message, a monday.com item, or Marketo drafts, each after a button press. Claude never sends an email or activates a campaign.
  • Agents create, never edit. They can add new Lucid diagrams but cannot change existing ones.

How this page mocks it

  • Nothing leaves the page. There are no network calls.
  • Tool names here are stand-ins. Each one maps to a real tool, listed on the cards above.
  • One sample data object. Every stand-in reads it, so the trace, the KPIs, and every result agree.
  • Going live means swapping each stand-in for its mapped call. The skill logic and the SKILL.md files stay the same.
Show a stand-in tool's code 
// A stand-in for a soqlQuery call on the real Salesforce server (see the table above).
// It reads the page's sample DATA object instead of calling an API.
const TOOLS = {
  'salesforce.query_leads': ({ noActivityHours, campaign }) => {
    let rows = DATA.slaLeads;                     // new leads, last 14 days
    if (noActivityHours) rows = rows.filter(l => l.hrs > noActivityHours);
    if (campaign)        rows = rows.filter(l => l.camp === campaign);
    return rows;
  },
};

// Every skill reaches data through call(), which also writes the run trace.
function call(tool, args = {}) {
  const out = TOOLS[tool](args);
  trace.push([tool, formatArgs(args), out.length + ' rows']);
  return out;
}

// A skill is then just tool calls plus rendering:
const late = call('salesforce.query_leads', { noActivityHours: 48 });
// In production this is an MCP tools/call request made with the user's OAuth token.
